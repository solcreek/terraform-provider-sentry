# Sentry Provider

An unofficial, community-maintained provider for [Sentry](https://sentry.io), built on the
[Sentry API](https://docs.sentry.io/api/). It manages teams, members, projects, team access to
projects, ownership rules, inbound filters and client keys (DSNs) in one organization, on sentry.io or a self-hosted install.
It supports both OpenTofu and Terraform.

Use the full `registry.opentofu.org/solcreek/sentry` source address with either CLI.

## Example Usage

```terraform
terraform {
  required_providers {
    sentry = {
      source = "registry.opentofu.org/solcreek/sentry"
    }
  }
}

provider "sentry" {
  # The auth token is read from the SENTRY_AUTH_TOKEN environment variable by
  # default; it can also be set explicitly here.
  # auth_token = "..."

  # Slug of the organization to manage; or the SENTRY_ORG environment variable.
  organization = "acme"

  # Optional: a self-hosted install or a region host.
  # base_url = "https://sentry.example.com"
}
```

## Authentication

Create an [internal integration](https://docs.sentry.io/organization/integrations/integration-platform/#internal-integrations)
in the organization's settings and pass its token through the `SENTRY_AUTH_TOKEN` environment
variable (or the `auth_token` argument). A personal token works too. The token needs these
[scopes](https://docs.sentry.io/api/permissions/):

| To manage | Scopes |
|-----------|--------|
| `sentry_team` | `team:admin` (create, rename, delete), plus `org:read` |
| `sentry_project`, `sentry_project_team`, `sentry_project_key` | `project:admin` |
| `sentry_project_ownership`, `sentry_project_inbound_filter` | `project:write` |
| `sentry_project_data_scrubbing` | `project:write` |
| `sentry_organization_data_scrubbing` | `org:write` |
| `sentry_organization_member` | `member:admin` (changing a role needs a personal token) |
| `sentry_team_member` | `team:write`, `org:write`, `member:read` |
| data sources only | `org:read`, `team:read`, `project:read`, `member:read` |

A `401` is reported as an invalid, expired or revoked token; a `403` as a missing scope.

## Lifecycle behavior

- Teams and projects are tracked by their numeric ID, not their slug. Renaming one, in
  Terraform or in Sentry, never replaces it. Reference them by `id`.
  A `project_id` argument also takes a slug, kept as written, but a slug stops resolving
  when the project is renamed.
- `sentry_project` defaults to `deletion_protection = true`, because deleting a project
  deletes its events and Sentry has no undo. Apply `false` before destroying.
- Sentry deletes teams and projects asynchronously: a destroy returns once Sentry has
  scheduled the deletion. They disappear from the API and free their slug at once.
- Client key rate limits are not part of every Sentry plan. Where the project lacks the
  `rate-limits` feature, the provider refuses `rate_limit` before creating or changing the key.
- A project always has an ownership configuration and every inbound filter, so
  `sentry_project_ownership` and `sentry_project_inbound_filter` take them over when created
  and reset them (no rules, filter off) when destroyed.
- `sentry_organization_member` sends an invitation by email when created.
- The data scrubbing resources change only the settings the configuration names, and
  destroying them leaves the settings in place.
- `sentry_project.default_rules` only applies when the project is created.
- Client key secrets (`secret_key`, `dsn_secret`) are marked sensitive but are stored in
  the state, like every attribute. Protect the state accordingly.

### Optional

- `auth_token` (String, Sensitive) Sentry auth token: the token of an internal integration (recommended) or a personal token. Falls back to the `SENTRY_AUTH_TOKEN` environment variable.
- `base_url` (String) Sentry base URL. Defaults to `https://sentry.io`; set it for a self-hosted install or a region host such as `https://de.sentry.io`. Falls back to `SENTRY_BASE_URL`.
- `organization` (String) Slug or ID of the organization to manage. Falls back to `SENTRY_ORG`.
- `timeout_seconds` (Number) Per-request HTTP timeout in seconds. Defaults to 60.
